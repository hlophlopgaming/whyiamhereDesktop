# Быстрый вход в репозиторий

«Зачем я здесь?» / Why am I here? — локальное приложение для KDE Plasma 6
и Wayland: спрашивает цель открытия программы, показывает таймер и завершает
сессию выбранным способом. Python 3.10+, PySide6 6.7–6.x, без сервера.
Общайся с пользователем на языке его запроса, обычно по-русски.

## С чего начать

- Выполни `git status --short`; сохраняй существующие изменения пользователя.
- Прочитай нужный модуль и его вызывающий код, затем соответствующие тесты.
- `README.ru.md` и `README.md` описывают пользовательское поведение;
  `TESTING.md` — проверки и ограничения реального KDE.
- Пользуйся существующей `.venv`. Команды ниже запускаются из корня репозитория.
- Не устанавливай зависимости заново, если окружение уже работает.

## Запуск и зависимости

Для нового окружения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
```

Безопасная демонстрация, без KWin, сохранения настроек и закрытия реальных программ:

```bash
.venv/bin/why-here --demo
.venv/bin/why-here --demo --language en
```

Обычный запуск: `.venv/bin/why-here`. Нужна сессия Plasma 6 / Wayland.
`--show` открывает настройки, `--background` запускает в трее.
Повторный обычный запуск обращается к уже работающему экземпляру через D-Bus.

## Карта кода

| Файл | Ответственность |
| --- | --- |
| `why_here/__main__.py` | CLI, QApplication, единственный экземпляр, подключение KWin |
| `why_here/core.py` | Engine, Session, идентификация окон, таймеры; без Qt и операций с процессами |
| `why_here/gui.py` | Controller, главное окно SettingsWindow, форма GoalDialog, напоминание Reminder, трей |
| `why_here/bridge.py`, `why_here/kwin.js` | Обмен через D-Bus, обнаружение и блокировка окон, команды KWin |
| `why_here/processes.py` | Linux pidfd, завершение дерева процессов, защита собственных и общих процессов |
| `why_here/storage.py` | Настройки JSON, история целей, каталог desktop-файлов, автозапуск |
| `why_here/i18n.py` | `tr()`, русский исходный текст и английские переводы |
| `why_here/assets/` | Иконки и логотипы |
| `install-desktop.sh` | Локальный пункт меню KDE; необязательный аргумент — путь к executable |
| `pyproject.toml` | Версия, зависимости, console script `why-here`, данные пакета |
| `build_binary.py` | Один исполняемый файл через PyInstaller |
| `.github/workflows/` | Автоматические проверки и публикация релиза по тегу |

Поток исполнения: KWin → Bridge → Controller → Engine; Controller обновляет
GUI и передаёт команды закрытия окон/завершения процессов соответствующим модулям.
Идентификатор приложения: `org.local.WhyHere` (`APP_ID` в `core.py`).

## Инварианты, которые важно сохранить

- Все окна одной программы делят сессию; программы имеют независимые таймеры.
- До ответа на форму таймер не запущен. В режиме закрытия окон форму нельзя
  отменить; в режиме SIGKILL её закрытие завершает отслеживаемую программу.
- Режим завершения фиксируется при старте сессии. Защиту процессов не упрощать.
- Таймер учитывает сон компьютера: используется `CLOCK_BOOTTIME`.
- Удаление/отключение отслеживания и выход из утилиты отменяют сессии без
  завершения отслеживаемых программ. Закрытие главного окна обычно прячет его в трей.
- Не обрезай `.desktop` у обычного ID без разбора: это может быть часть имени.
- Новые пользовательские строки оборачивай в `tr()` и добавляй перевод.
  Смена языка в настройках применяется после перезапуска.
- Версия берётся из metadata установленного пакета (`pyproject.toml`);
  сборка должна сохранять `--copy-metadata why-am-i-here-kde`.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen .venv/bin/python -m tests.gui_smoke
QT_QPA_PLATFORM=offscreen .venv/bin/python -m tests.startup_smoke
QT_QPA_PLATFORM=offscreen .venv/bin/python -m tests.english_smoke
bash -n install-desktop.sh
git diff --check
```

Выбирай проверки по изменению: unittest для логики, GUI smoke для интерфейса,
`tests.test_desktop_install` и `bash -n` для установочного скрипта.
Предупреждения offscreen о трее/raise ожидаемы. Headless-проверки не подтверждают
реальную работу KWin. Проверки в Plasma, включая SIGKILL тестовых процессов,
описаны в `TESTING.md`; не проверяй завершение на пользовательских программах.

`tests.english_smoke` перезаписывает `artifacts/settings-en.png` и
`artifacts/reminder-en.png`. Проверь diff: не оставляй случайные изменения снимков
и не затирай снимки, которые пользователь изменил до твоей работы.
Не запускай установщик на настоящем профиле только ради теста: используй
временный `XDG_DATA_HOME`, как в `tests/test_desktop_install.py`.

## Сборка и локальные файлы

```bash
.venv/bin/python -m pip install -r requirements-build.txt
.venv/bin/python build_binary.py
./dist/why-here --demo
```

Сборка нужна при изменениях упаковки или по запросу; для обычной правки GUI
достаточно проверок из исходников. Релизный тег `v<версия>` должен совпадать
с `pyproject.toml`. Не публикуй релизы и не отправляй теги без запроса пользователя.

Настройки: `${XDG_CONFIG_HOME:-~/.config}/why-here/settings.json`.
Автозапуск: `${XDG_CONFIG_HOME:-~/.config}/autostart/org.local.WhyHere.desktop`.
Пункт меню: `${XDG_DATA_HOME:-~/.local/share}/applications/org.local.WhyHere.desktop`.
Не меняй личные настройки пользователя ради проверки.

Следуй `.editorconfig`: табы в Python/Bash, два пробела в YAML, UTF-8 и LF.
Предпочитай небольшие изменения, стандартную библиотеку и уже имеющиеся зависимости.
Не добавляй сгенерированные `build/`, `dist/`, `.venv/`, кеши и egg-info в Git.
Обновляй оба README при изменении пользовательских команд или поведения.

Этот `AGENTS.md` предназначен для хранения в репозитории. Поддерживай инструкции
в актуальном состоянии при изменении команд и структуры проекта.
Для личных исключений используй `.git/info/exclude`, не `skip-worktree`.
